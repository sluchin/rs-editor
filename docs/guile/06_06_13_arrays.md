#### 6.6.13 配列

配列とは、任意の次元に構成されたセルの集合です。各セルには、各次元に対応するインデックスを指定することで、定数時間でアクセスできます。

現在の実装では、配列は要素の実際の格納に何らかのベクトルを使用します。どのような種類のベクトルでも構わないため、均一な数値の配列、文字の配列、ビットの配列、そしてもちろん、任意のScheme値の配列を作成できます。たとえば、基となる`c64vector`を持つ配列はデジタル信号処理に適しているかもしれませんし、`u8vector`から作成された配列はグレースケール画像を格納するために使用できるかもしれません。

配列の次元数をランクと呼びます。したがって、行列はランク2の配列であり、ベクトルはランク1の配列です。配列要素にアクセスする際には、各次元に対して正確な整数を1つ指定する必要があります。これらの整数は、要素のインデックスと呼ばれます。配列は、各次元のインデックスの許容範囲を、下限と上限を含む値で指定します。これらの範囲は負の値でも構いませんが、上限は下限から1を引いた値以上でなければなりません。配列の下限がすべて0の場合、その配列はゼロ原点配列と呼ばれます。

配列はランク0になることもあり、これはスカラーとして解釈できます。したがって、ランク0の配列には正確に1つのオブジェクトを格納でき、その要素のインデックスのリストは空のリストになります。

配列は、いずれかの次元の長さがゼロの場合、要素がゼロになります。これらの空の配列は、その形状に関する情報を保持しています。つまり、列数がゼロで行数が3の行列は、列数が3で行数がゼロの行列とは異なり、さらに長さがゼロのベクトルとも異なります。

配列操作はすべて多態性があり、文字列、均一な数値ベクトル、バイトベクトル、ビットベクトル、および通常のベクトルを1次元配列として扱います。

#### 6.6.13.1 配列構文

配列は、`#` の後にランク、基となるベクトルを説明するタグ、オプションでその形状に関する情報、そして最後に括弧を使用して次元ごとに整理されたセルが続く形で表示されます。

言い換えると、配列タグは次の形式です。

#<rank><vectag><@lower><:len><@lower><:len>...

ここで、`<rank>` は配列のランクを表す正の整数（10進数）です。ランクが 1 で、配列が共有されておらず、原点がゼロの場合（下記参照）は省略されます。共有配列で原点がゼロでない場合は、通常のベクトルと区別するために、ランクが 1 の場合でも常に表示されます。

`<vectag>` の部分は、`u8`、`s16` などの均一な数値ベクトル、ビットベクトルの場合は `b`、文字列の場合は `a` といったタグです。通常のベクトルの場合は空になります。

`<@lower>` 部分は、'@' 文字の後に符号付き整数 (10 進数) が続く形式で、次元の下限値を表します。各次元につき 1 つの `<@lower>` があります。すべての下限値がゼロの場合、すべての `<@lower>` 部分は省略されます。

`<:len>` 部分は、コロン (:) と、次元の長さを表す符号なし整数 (10 進数) で構成されます。下限値と同様に、各次元に `<:len>` が 1 つずつあり、`<:len>` 部分は常に次元の `<@lower>` 部分の後に続きます。長さは、配列リテラルのネストされた要素リストから推測できない場合にのみ出力されます。これは、少なくとも 1 つの長さがゼロの場合に発生する可能性があります。

特殊なケースとして、ランク0の配列は`#0<vectag>(<scalar>)`と出力されます。ここで`<scalar>`は配列の単一要素を出力した結果です。

したがって、

`#(1 2 3)`

は、次元0において下限が0である、ランク1の通常の配列です。（つまり、通常のベクトルです。）

`#@2(1 2 3)`

は、次元0における下限が2のランク1の通常の配列です。

`#2((1 2 3) (4 5 6))`

はランク 2 の非均一配列です。インデックス範囲が 0..1 と 0..2 の 2x3 行列です。

`#u8(0 1 2)`

はランク1の均一なu8配列です。

`#2u32@2@3((1 2) (2 3))`

は、インデックス範囲が 2..3 および 3..4 のランク 2 の一様 u32 配列です。

`#2()`

これは、インデックス範囲が 0..-1 と 0..-1 の 2 次元配列であり、つまり両方の次元の長さはゼロです。

`#2:0:2()`

これは、インデックス範囲が 0..-1 と 0..1 の 2 次元配列です。つまり、最初の次元の長さはゼロですが、2 番目の次元の長さは 2 です。

`#0(12)`

は、内容が12であるランクゼロ配列です。

さらに、バイトベクトルも配列ですが、構文が異なります（[バイトベクトル](06_06_12_bytevectors.md#6612-バイトベクトル)を参照）。

`#vu8(1 2 3)`

これは、内容が 1、2、3 である 3 バイト長のバイトベクトルです。

#### 6.6.13.2 配列プロシージャ

配列を作成する際には、各次元の範囲を指定する必要があります。例えば、0から始まるインデックスを持つ2x3配列を作成するには、次のように指定します。

(make-array 'ho 2 3) ⇒ #2((ほほほ) (ほほほ))

各次元の範囲を明示的に指定することもできます。例えば、同じ配列を作成する別の方法として、次のようになります。

(make-array 'ho '(0 1) '(0 2)) ⇒ #2((ほほほ) (ほほほ))

以下の手順は配列（またはベクトル）で使用できます。idx…と表記される引数は、配列の各次元に対応するパラメータを意味します。idxlist引数は、各次元に対応する値のリストを意味します。

Scheme手順: **array?** obj

C 関数: **scm\_array\_p** (obj、未使用)

objが配列の場合は`#t`を返し、そうでない場合は`#f`を返します。

scm_array_p の 2 番目の引数は、歴史的な理由から存在しますが、使用されていません。常に `SCM_UNDEFINED` を値として渡す必要があります。

Scheme 手順: **typed-array?** obj type

C 関数: **scm\_typed\_array\_p** (obj, type)

obj が type の配列である場合は `#t` を返し、そうでない場合は `#f` を返します。

C 関数: `int` **scm\_is\_array** `(SCM obj)`

objが配列の場合は`1`を、そうでない場合は`0`を返します。

C 関数: `int` **scm\_is\_typed\_array** `(SCM オブジェクト、SCM タイプ)`

obj が type の配列である場合は 0 を返し、そうでない場合は 1 を返します。

Scheme 手順: **make-array** 境界を埋める…

C 関数: **scm\_make\_array** (fill, bounds)

`(make-typed-array #t fill bound ...)` と同等です。

Scheme 手順: **make-typed-array** type fill bound …

C 関数: **scm\_make\_typed\_array** (型、塗りつぶし、境界)

境界と同じ次元数を持つ配列を作成し、返します。そして（場合によっては）その配列をfillで埋めます。

基となるストレージベクトルは型に応じて作成されます。型は、上記で説明した配列の「vectag」と同じ名前のシンボル、または通常の特殊化されていない配列の場合は「#t」である必要があります。

例えば、型にシンボル `f64` を使用すると、要素を格納するために `f64vector` を使用する配列が作成され、`a` を使用すると文字列が使用されます。

fill が特別な _unspecified_ 値でない場合、新しい配列は fill で埋められます。それ以外の場合、配列の初期内容は未指定です。特別な _unspecified_ 値は変数 `*unspecified*` に格納されるため、たとえば `(make-typed-array 'u32 *unspecified* 4)` は、長さ 4 の初期化されていない `u32` ベクトルを作成します。

各境界は、正の非ゼロ整数 n である場合があり、その場合、その次元のインデックスは 0 から n-1 までの範囲になります。または、`(LOWER UPPER)` の形式の明示的なインデックス範囲指定子で、lower と upper はどちらも整数であり、0 未満の場合もあり、同じ数値の場合もあります (ただし、lower は upper より大きくすることはできません)。

`(list->typed-array #t dimspec list)` と同等です。

Scheme 手順: **list->typed-array** type dimspec list

C 関数: **scm\_list\_to\_typed\_array** (type, dimspec, list)

typeで指定された型の配列を返します。配列の要素はlistの要素と同じです。

引数 dimspec は、配列の次元数とその下限値を指定します。dimspec が整数の場合、次元数が直接指定され、すべての下限値はゼロになります。整数のリストの場合、各要素は次元の下限インデックスとなり、リストの要素数と同じ数の次元が存在します。

Scheme手順: **array-type** array

C 関数: **scm\_array\_type** (配列)

配列の型を返します。これは配列を出力する際に使用される「vectag」（通常の配列の場合は「#t」）であり、`make-typed-array` と組み合わせて、配列と同じ種類の配列を作成するために使用できます。

Scheme手順: **array-ref** array idx …

(define a (make-array #f '(1 2) '(3 4)))

Scheme 手順: **array-set!** array obj idx …

(define a (make-array #f '(0 1) '(0 1)))

a ⇒ #2((#f #f) (#f #t))

Scheme手順: **array-shape** array

C 関数: **scm\_array\_dimensions** (配列)

(define a (make-array 'foo '(-1 3) 5))

配列のすべての要素に値を格納します。返される値は未指定です。

すべての引数が同じ形状、同じ型の配列であり、対応する要素が `equal?` または `array-equal?` のいずれかである場合、`#t` を返します。この関数は、すべての引数が配列である必要があるという点で `equal?` ([Equality](06_09_general_utility_functions.md#691-平等) を参照) とは異なります。

Scheme Procedure: **array-map!** dst proc src …

Scheme Procedure: **array-map-in-order!** dst proc src …

C 関数: **scm\_array\_map\_x** (dst, proc, srclist)

dst配列の各要素を、proc呼び出しから取得した値に設定します。src引数のリストは空でも構いません。返される値は未指定です。

各呼び出しは `(proc elem …)` の形式で、各 elem は対応する src 配列の dst インデックスから取得されます。`array-map-in-order!` は呼び出しを行優先順で実行し、`array-map!` は順序を指定せずに実行します。

src配列はdstと同じ次元数を持つ必要があり、各次元の範囲はdstの範囲を網羅している必要があります。これにより、すべてのdstインデックスが各srcで有効であることが保証されます。

Scheme プロシージャ: **array-for-each** proc src1 src2 …

C 関数: **scm\_array\_for\_each** (proc, src1, srclist) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index- scm_005farray_005ffor_005feach)

src1 src2 …の各要素のタプルに対して、行優先順でプロシージャを適用します。返される値は未指定です。

Scheme プロシージャ: **array-index-map!** dst proc

C 関数: **scm\_array\_index\_map\_x** (dst, proc)

dst配列の各要素を、proc呼び出しによって返される値に設定します。返される値は未指定です。

各呼び出しは `(proc i1 … iN)` という形式で行われ、i1…iN は宛先インデックス、各次元ごとに 1 つのパラメータが渡されます。呼び出しの順序は指定されていません。

例えば、巡回群を表す _4x4_ 行列を作成するには、

/ 0 1 2 3 \\
| 1 2 3 0 |
| 2 3 0 1 |
\\ 3 0 1 2 /

(define a (make-array #f 4 4))
(配列インデックスマップ! a (ラムダ (ij)
(mod (+ ij) 4)))

モジュール`(ice-9 arrays)`には、追加の配列関数が用意されています。これは以下と組み合わせて使用できます。

(use-modules (ice-9 arrays))

Scheme手順: **array-copy** src

src と同じ要素、型、形状を持つ新しい配列を返します。ただし、配列のインクリメントは src と異なる場合があります。現在の実装では、返される配列は行優先順になりますが、将来変更される可能性があります。順序が気になる場合は、既知の順序の配列に対して `array-copy!` を使用してください。

#### 6.6.13.3 共有配列

Scheme 手順: **make-shared-array** oldarray mapfunc bound …

C 関数: **scm\_make\_shared\_array** (oldarray、mapfunc、boundlist)

oldarray のストレージを共有する新しい配列を返します。どちらの配列で行われた変更も、同じ基となるストレージに影響します。bound … 引数は新しい配列の形状であり、`make-array` と同じです ([配列プロシージャ](#66132-配列プロシージャ) を参照)。

mapfunc は、新しい配列の座標を古い配列に変換します。呼び出しは `(mapfunc newidx1 …)` の形式で、新しい配列の各次元に対応するパラメータを 1 つずつ指定します。戻り値は、古い配列の各次元に対応するインデックスのリストです。

mapfuncはアフィン線形関数でなければなりません。つまり、各oldarrayインデックスは、newidx1などの一部または全部の整数倍（負の値も可）と、場合によっては整数オフセットを加算して形成されなければなりません。倍数とオフセットは、呼び出しごとに同じでなければなりません。

  

共有配列の便利な使い方の1つは、一部の次元の範囲を制限して、配列の一部にのみ`array-for-each`や`array-fill!`などを適用することです。この場合、通常の`list`関数をmapfuncに使用でき、インデックス値に変更を加えることはありません。たとえば、

(make-shared-array #2((abc) (def) (ghi)) list 3 2)
⇒ #2((ab) (de) (gh))

新しい配列は、古い配列よりも次元数が少なくても構いません。例えば、配列から列を取り出す場合などです。

(make-shared-array #2((abc) (def) (ghi))
(lambda (i) (list i 2))
（0 2）
⇒ #1(cfi)

対角線は、古い配列の行と列の両方に新しい配列のインデックスを1つ使用することで取得できます。たとえば、

(make-shared-array #2((abc) (def) (ghi))
(ラムダ (i) (リスト ii))
（0 2）
⇒ #1(aei)

例えば、一次元配列の一部を二次元配列の行として扱うことで、次元を増やすことができます。（下記の`array-contents`は、その逆の操作、つまり配列を平坦化することができます。）

(make-shared-array #1(abcdefghijkl)
(lambda (ij) (list (+ (\* i 3) j)))
4 3)
⇒ #2((abc) (def) (ghi) (jkl))

インデックスを否定することで、要素の出現順序を反転させることができます。以下は列の順序を反転させるだけです。

(make-shared-array #2((abc) (def) (ghi))
(lambda (ij) (list i (- 2 j)))
3 3)
⇒ #2((cba) (fed) (ihg))

インデックスに固定オフセットを設定することで、例えば0ベースの配列から1ベースの配列への変更が可能になります。

(define x #2((abc) (def) (ghi)))
(define y (make-shared-array x
(lambda (ij) (list (1- i) (1- j)))
'(1 3) '(1 3)))
(配列参照 x 0 0) ⇒ a
(配列参照 y 1 1) ⇒ a

インデックスの倍数を使用すると、配列のN番目の要素を取得できます。以下は3番目の要素です。

(make-shared-array #1(abcdefghijkl)
(lambda (i) (list (\* i 3)))
4)
⇒ #1(adgj)

上記の例を組み合わせることで、配列から奇妙で素晴らしい選択を行うことができますが、mapfuncはアフィン線形でなければならないため、任意の順列は不可能であることに注意することが重要です。

現在の実装では、mapfuncは新しい配列へのアクセスごとに呼び出されるのではなく、いくつかのサンプルポイントでのみ呼び出され、古い配列データ内の新しい配列インデックスのベースとストライドを確立します。mapfuncは線形であるため、少数のサンプルポイントで十分です。

Scheme Procedure: **shared-array-increments** array

C 関数: **scm\_shared\_array\_increments** (配列)

各次元について、ルートベクトル内の要素間の距離を返します。

Scheme Procedure: **shared-array-offset** array

C 関数: **scm\_shared\_array\_offset** (配列)

配列の最初の要素のルートベクトルのインデックスを返します。

Scheme 手順: **array-contents** array \[strict\]

C 関数: **scm\_array\_contents** (配列、厳密)

配列が順序を変更せずに（最後の添え字が最も速く変化するように）1次元の共有配列に展開できる場合、`array-contents` はその共有配列を返します。そうでない場合は `#f` を返します。`make-array` および `make-typed-array` で作成されたすべての配列は展開できますが、`make-shared-array` で作成された配列の中には展開できないものもあります。

Scheme手順: **transpose-array** array dim1 dim2 …

C 関数: **scm\_transpose\_array** (array, dimlist)

元の配列と同じ内容を持つ配列を返しますが、次元の順序が異なります。配列の各次元に対応するdim引数が1つ必要です。dim1、dim2、…は、0から返される配列のランクまでの整数である必要があります。この範囲の各整数は、引数リストに少なくとも1回出現する必要があります。

dim1、dim2、…の値は、返される配列の次元に対応し、引数リストにおけるそれらの位置は配列の次元に対応します。複数のdimが同じ値を持つ場合、返される配列のランクは元の配列よりも小さくなります。

#2((a 4) (b 5) (c 6))

#### 6.6.13.4 配列の配列としての配列

ランク n の配列 (n \-配列) は、要素自体が配列 (「セル」) である、より低いランクの配列と見なすことができます。

配列の最初の _n-k_ 次元を配列の _n-k_ 'フレーム' と呼び、最後の _k_ 次元を _k_ 'セル' の次元と呼びます。例えば、3 次元配列は、ベクトル (1 次元配列) の 2 次元配列、または行列 (2 次元配列) の 1 次元配列と見なすことができます。いずれの場合も、ベクトルまたは行列は配列の 1 次元セルまたは 2 次元セルです。この用語は J 言語に由来します。

より曖昧な概念である「スライス」とは、配列のサブセットを指し、一部のインデックスは固定され、その他は自由に選択できます。Guileのデータオブジェクトとして、セルは「プレフィックススライス」（元の配列の最初の_n-k_個のインデックスが固定されている）と同じですが、0セルは元の配列の共有配列ではありませんが、0スライス（元の配列のすべてのインデックスが固定されている）は共有配列です。

バージョン2.0より前のGuileには、「囲まれた配列」と呼ばれる機能があり、特殊な「配列の配列」オブジェクトを作成できました。このセクションの関数は特別な型を必要としません。代わりに、フレームランクは引数で暗黙的に（インデックスの数によって）または明示的に指定されます。

#### 6.6.13.5 C言語から配列にアクセスする

外部のCコードとの連携のために、GuileはCコードからScheme配列の要素にアクセスできるAPIを提供します。特に、均一な数値配列の場合、このAPIは基となる均一データを、該当する型の数値のC配列として公開します。

配列の要素へのポインタが使用されている間は、ポインタが有効であり続けるように、配列自体を保護する必要があります。このように保護された配列は「予約済み」と呼ばれます。予約済みの配列は読み取り可能ですが、要素へのポインタが無効になるような変更はできません。そのような変更を試みると、エラーが発生します。

（これは、配列を使用中にロックするのと似ていますが、デッドロックの危険性はありません。マルチスレッドプログラムでは、予約済みの配列を変更しないように、追加の同期処理が必要になります。）

非ローカル終了が発生する場合でも、配列を予約した後は必ず予約を解除するように注意してください。これら 2 つの呼び出しの間に非ローカル終了が発生する可能性がある場合は、配列が終了時に解放される dynwind コンテキストをインストールする必要があります ([Dynamic Wind](06_11_controlling_the_flow_of_program_execution.md#61110-ダイナミックウィンド) を参照)。

さらに、配列の予約と予約解除は適切にペアリングする必要があります。例えば、2つ以上の配列を特定の順序で予約した場合、予約解除は逆の順序で行う必要があります。

配列を予約し、その要素へのポインタを取得したら、メモリ内の要素の配置を把握する必要があります。Guileでは、実際にコピーを作成することなく配列からスライスを取り出すことができます。例えば、ベクトルとして扱える行列の対角線にエイリアスを作成する場合などです。このような操作によって生成された配列はメモリ上に連続して格納されないため、要素を直接操作する際には、この点を考慮する必要があります。

メモリ内の配列要素の配置は、インデックスのベクトルからスカラー位置を計算するマッピング関数によって定義できます。このスカラー位置は、指定されたインデックスを持つ要素が配列の記憶ブロックの先頭からどれだけ離れているかを示すオフセット値です。

Guile では、このマッピング関数は _アフィン _ に制限されています。Guile 配列のすべてのマッピング関数は、`p = b + c[0]*i[0] + c[1]*i[1] + ... + c[n-1]*i[n-1]` と記述できます。ここで、`i[k]` は `k` 番目のインデックス、`n` は配列のランクです。たとえば、3x3 サイズの行列では、`b == 0`、`c[0] == 3`、`c[1] == 1` となります。この行列を転置すると (たとえば `transpose-array` を使用)、マッピング関数が `b == 0`、`c[0] == 1`、`c[1] == 3` となる配列が得られます。

関数 `scm_array_handle_dims` を使用すると、係数 `c[k]` に（間接的に）アクセスできます。

現時点では、文字配列の要素にアクセスするための関数は用意されていません。Guileの文字列実装がUnicodeに対応するよう変更され次第、これらの関数を提供する予定です。

C 型: **scm\_t\_array\_handle**

これは、前述のように配列の予約を管理するために必要なすべての情報を保持する構造体型です。この型の構造体はスタック上に割り当てられ、以下の関数からのみアクセス可能です。

C 関数: `const scm_t_uint32 *` **scm\_array\_handle\_bit\_elements** `(scm_t_array_handle *handle)`

表現対象の配列のビットを格納するワードへのポインタを返します。表現対象の配列はビット配列である必要があります。

他の配列とは異なり、ビット配列にはインデックス計算に含める必要がある追加のオフセットがあります。このオフセットは`scm_array_handle_bit_elements_offset`によって返されます。

特定のビットを見つけるには、まず`scm_array_handle_dims`について上述したようにその位置を計算し、次にオフセットを加算する必要があります。これにより、ビットの絶対位置が得られます。絶対位置は常に非負の整数です。

ビット配列格納ブロックの各ワードは正確に32ビットで構成され、そのワードの最下位ビットは絶対位置番号が最も小さい。次のワードには次の32ビットが含まれる。
