#### 7.5.9 SRFI-10 - ハッシュカンマリーダー拡張機能 [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#SRFI_002d10-_002d-Hash_002dComma-Reader-Extension)

この SRFI は、ハッシュ カンマと呼ばれるリーダー拡張機能 `#,()` を実装しています。これにより、リーダーはデータ内およびソース コード内の定数またはリテラルとして使用できる新しい種類のオブジェクトを提供できます。この機能は以下で利用可能です。

(use-modules (srfi srfi-10))

新しい読み取り構文は次の形式です。

#,(タグ引数...)

ここで、tag はシンボルであり、args はパラメータとして渡されるオブジェクトです。タグは、以下の手順で登録されます。

Scheme プロシージャ: **define-reader-ctor** タグ proc [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-define_002dreader_002dctor)

proc を、シンボル tag で始まるハッシュカンマ読み取り構文のコンストラクタとして登録します。つまり、`#,(tag arg…)` です。proc は指定された引数 `(proc arg…)` で呼び出され、返されるオブジェクトは読み取りの結果です。

例えば、オブジェクトのN個のコピーのリストを示す構文など。

(define-reader-ctor 'repeat
(ラムダ (オブジェクト表現)
(make-list reps obj)))

(display '#,(repeat 99 3))
⊣ (99 99 99)

`#,( )` を使用する際に引用符 `'` があることに注意してください。`repeat` ハンドラはリストを返すため、他のリストと同様に、プログラムでそれを文字通り使用するには引用符を付ける必要があります。つまり、

(display '#,(repeat 99 3))
⇒
(display '(99 99 99))

ハンドラが数値や文字列などの自己評価オブジェクトを返す場合、それらをリテラルとして直接渡す場合と同様に、引用符は必要ありません。たとえば、加算の場合、

(define-reader-ctor 'sum
(ラムダ (xy)
(+ xy)))
(表示番号、(合計 123 456)) ⊣ 579

`(srfi srfi-10)` がロードされると、`#,()` がグローバルに利用可能になるため、後続のモジュールで `(srfi srfi-10)` を使用する必要はありません。同様に、登録されたタグはグローバルであり、一度登録すればどこでも使用できます。

ただし、`#,()` リーダー拡張機能は推奨しません。理由は 3 つあります。

まず、このSRFIはモジュール化されていません。タグはスコープ内の識別子としてではなく、名前によって照合されます。そのため、プログラムのある部分でリーダー拡張機能を定義すると、タグにスコープが設定されていないため、プログラムの無関係な部分に影響を与える可能性があります。

第二に、リーダー拡張機能は時間的な観点から管理が難しい場合があります。リーダー拡張機能はいつ有効になるのでしょうか？詳細については、[Eval-when](https://doc.guix.gnu.org/guile/latest/en/guile.html#Eval-When)を参照してください。

最後に、リーダー拡張機能は、コンパイラによってオブジェクトファイルに具体化できないオブジェクトを簡単に生成してしまう可能性があります。たとえば、ハッシュテーブルを作成するリーダー拡張機能を定義した場合（[ハッシュテーブル](https://doc.guix.gnu.org/guile/latest/en/guile.html#Hash-Tables)を参照）、インタープリタで実行すると問題なく動作し、巧妙なハックができたと思うかもしれません。しかし、上記の`eval-when`に関する問題に対処した後、プログラムをコンパイルしようとすると、コンパイラはハッシュテーブルをディスクにシリアル化する方法がわからないと警告します。

ハッシュテーブルの場合、Guile がハッシュテーブルをコンパイル済みファイルにパックする方法を知ることは可能ですが、これは一般的には機能しません。生成するオブジェクトがレコード型のインスタンスである場合はどうでしょうか。その場合、Guile はレコード型もディスクにシリアル化する必要があります。さらに、プログラムがレコード型を定義するコードを独自にロードした場合、どうなるでしょうか。同じ型が定義されるのでしょうか、それとも異なる型が定義されるのでしょうか。Guile のレコード型は名目上のものであり、構造的なものではないため、答えは全く明確ではありません。

これらの理由から、リーダー拡張機能よりもマクロの使用をお勧めします。マクロはモジュール構成を維持しながら、多くの同様のニーズを満たし、`eval-when` との連携もよく知られています。簡潔さが求められる場合は、代わりに `read-hash-extend` を使用し、リーダー拡張機能をマクロ呼び出しに展開してください。そうすることで、スコープを可能な限り維持できます。[リーダー拡張機能](https://doc.guix.gnu.org/guile/latest/en/guile.html#Reader-Extensions) を参照してください。
