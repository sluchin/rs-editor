#### 6.6.9.1 リスト読み取り構文 [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#List-Read-Syntax)

リストの構文は、開き括弧、次にリストのすべての要素（空白で区切る）、最後に閉じ括弧です。[10](https://doc.guix.gnu.org/guile/latest/en/guile.html#FOOT10)。

（1 2 3） ; 1、2、3の数字のリスト
（"foo" bar 3.1415）; 文字列、記号、実数
() ; 空のリスト

最後の例については、もう少し説明が必要です。要素を持たないリスト、つまり「空リスト」は、いくつかの点で特殊です。これは、リストを構成する最後のペアのcdrに格納することで、リストを終了するために使用されます。例を挙げれば、それがよくわかります。

([car](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-car) '(1))
⇒
1
([cdr](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-cdr) '(1))
⇒
（）

この例は、リストを記述する際には引用符で囲む必要があることも示しています（[式構文](https://doc.guix.gnu.org/guile/latest/en/guile.html#Expression-Syntax)を参照）。そうしないと、誤って手続きの適用とみなされてしまうためです（[単純な手続きの呼び出し](https://doc.guix.gnu.org/guile/latest/en/guile.html#Simple-Invocation)を参照）。

#### 6.6.9.2 リスト述語 [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#List-Predicates-1)

与えられたSchemeオブジェクトがリストであるかどうかを判定することは、しばしば有用です。リスト処理プロシージャは、この情報を使用して入力が有効かどうかを判定したり、引数のデータ型に応じて異なる処理を実行したりできます。

スキーム手順: **list?** x [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-list_003f)

C 関数: **scm\_list\_p** (x) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005fp)

xが適切なリストであれば`#t`を返し、そうでなければ`#f`を返します。

述語`null?`は、リスト処理コードにおいて、与えられたリストの要素が尽きたかどうかを判断するためによく使用されます。つまり、ループはリストの要素を処理し、リストが`null?`を満たすまで処理を続けます。そして、条件が満たされるとアルゴリズムは終了します。

Scheme Procedure: **null?** x [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-null_003f)

C 関数: **scm\_null\_p** (x) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fnull_005fp)

xが空のリストの場合は`#t`を返し、そうでない場合は`#f`を返します。

C 関数: `int` **scm\_is\_null** `(SCM x)` [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fis_005fnull)

xが空リストの場合は1を返し、それ以外の場合は0を返します。

#### 6.6.9.3 リストコンストラクタ [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#List-Constructors-1)

このセクションでは、新しいリストを作成する手順について説明します。`list` は引数を要素とするリストを返します。`cons*` も同様ですが、最後の引数はリストの最後のペアの cdr に格納されます。

Scheme手順: **list** elem … [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-list-1)

C 関数: **scm\_list\_1** (elem1) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005f1)

C 関数: **scm\_list\_2** (elem1, elem2) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005f2)

C 関数: **scm\_list\_3** (elem1, elem2, elem3) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005f3)

C 関数: **scm\_list\_4** (elem1, elem2, elem3, elem4) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005f4)

C 関数: **scm\_list\_5** (elem1, elem2, elem3, elem4, elem5) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005f5)

C 関数: **scm\_list\_n** (elem1, …, elemN, `SCM_UNDEFINED`) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005fn)

要素 elem ... を含む新しいリストを返します。

`scm_list_n` は可変個の引数を受け取り、特殊な `SCM_UNDEFINED` で終了します。この最後の `SCM_UNDEFINED` はリストには含まれません。要素 … のいずれも `SCM_UNDEFINED` であってはならず、そうである場合は `scm_list_n` はその時点で終了します。

Scheme Procedure: **cons\*** arg1 arg2 … [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-cons_002a)

`list` と同様ですが、最後の引数は構築されたリストの末尾を提供し、`(cons arg1 (cons arg2 (cons … argn)))` を返します。少なくとも 1 つの引数が必要です。引数が 1 つだけ与えられた場合、その引数が結果として返されます。この関数は、他の Schemes や Common LISP では `list*` と呼ばれています。

Scheme Procedure: **list-copy** lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-list_002dcopy)

C 関数: **scm\_list\_copy** (lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005flist_005fcopy)

lst の（新しく作成された）コピーを返します。

Scheme手順: **make-list** n \[init\] [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-make_002dlist)

n個の要素を含むリストを作成します。各要素はinitで初期化されます。initが指定されていない場合、デフォルトで空のリスト`()`が使用されます。

`list-copy` はリストの基幹を構成するペアのみをコピーすることに注意してください。リストの要素はコピーされないため、新しいリストの要素を変更すると、古いリストの要素も変更されます。一方、`set-cdr!` や `delv!` などのプロシージャを新しいリストに適用しても、古いリストは変更されません。リストの要素もコピーする必要がある場合（ディープコピーを作成する場合）は、`(ice-9 copy-tree)` の `copy-tree` プロシージャを使用してください（[ディープ構造のコピー](https://doc.guix.gnu.org/guile/latest/en/guile.html#Copying) を参照）。

#### 6.6.9.5 追加と逆順 [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#Append-and-Reverse)

`append` と `append!` は、2 つ以上のリストを連結して新しいリストを作成するために使用されます。`reverse` と `reverse!` は、引数と同じ要素を持つリストを逆順で返します。`!` が付いたプロシージャは、リストを構成するペアを直接変更しますが、その他のプロシージャは新しいペアを作成します。そのため、副作用のあるプロシージャを使用する際には注意が必要です。

Scheme Procedure: **append** lst … obj [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append)

Scheme Procedure: **append** [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append-1)

Scheme 手順: **append!** lst … obj [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append_0021)

Scheme 手順: **append!** [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append_0021-1)

C 関数: **scm\_append** (lstlst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fappend)

C 関数: **scm\_append\_x** (lstlst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fappend_005fx)

リスト lst … obj のすべての要素を含むリストを返します。引数なしで呼び出された場合は、空のリストを返します。

([append](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append) '(x) '(y)) ⇒ (xy)
([append](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append) '(a) '(bcd)) ⇒ (abcd)
([append](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append) '(a (b)) '((c))) ⇒ (a (b) (c))

最後の引数 obj は実際には任意のオブジェクトを指定できます。最後の引数が適切なリストでない場合は、不適切なリストが生成されます。

([append](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append) '(ab) '(c . d)) ⇒ (abc . d)
([append](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-append) '() 'a) ⇒ a

`append` は指定されたリストを変更しませんが、戻り値は最終的なオブジェクトと同じ構造を持つ場合があります。`append!` は、戻り値を生成するために指定されたリストを変更することが許可されていますが、必須ではありません。

`scm_append` および `scm_append_x` の場合、lstlst はリストオペランド lst … obj のリストです。この lstlst 自体は変更されず、戻り値にも使用されません。

Scheme手順: **reverse** lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-reverse)

Scheme Procedure: **reverse!** lst \[newtail\] [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-reverse_0021)

C 関数: **scm\_reverse** (lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005freverse)

C 関数: **scm\_reverse\_x** (lst、newtail) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005freverse_005fx)

lstの要素を逆順に並べたリストを返します。

`reverse`は新しいリストを構築します。`reverse!`は、戻り値を構築する際にlstを変更することが許可されていますが、必須ではありません。

`reverse!` の場合、オプションの newtail が結果に追加されます。newtail は逆順にはならず、単にリストの末尾になります。`scm_reverse_x` の場合、newtail パラメータは必須ですが、末尾が不要な場合は `SCM_EOL` を指定できます。

スキーム手順: **delete** アイテム lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delete)

拡張された `delete` ([削除](https://doc.guix.gnu.org/guile/latest/en/guile.html#SRFI_002d1-Deleting))と、1 回の呼び出しで複数の項目を削除できる `lset-difference` ([リストに対するセット操作](https://doc.guix.gnu.org/guile/latest/en/guile.html#SRFI_002d1-Set-Operations)) を備えた SRFI-1 も参照してください。

Scheme Procedure: **delq!** item lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delq_0021)

Scheme Procedure: **delv!** item lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delv_0021)

スキーム手順: **delete!** アイテム lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delete_0021)

C 関数: **scm\_delq\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelq_005fx)

C 関数: **scm\_delv\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelv_005fx)

C 関数: **scm\_delete\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelete_005fx)

スキーム手順: **delq1!** item lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delq1_0021)

C 関数: **scm\_delq1\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelq1_005fx)

`delq!` と同様ですが、lst から項目の最初の出現箇所のみを削除します。`eq?` を使用して等価性をテストします。`delv1!` および `delete1!` も参照してください。

スキーム手順: **delv1!** item lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delv1_0021)

C 関数: **scm\_delv1\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelv1_005fx)

`delv!` と同様ですが、lst から項目の最初の出現箇所のみを削除します。等価性の判定には `eqv?` を使用します。`delq1!` および `delete1!` も参照してください。

スキーム手順: **delete1!** item lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-delete1_0021)

C 関数: **scm\_delete1\_x** (item, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fdelete1_005fx)

`delete!` と同様ですが、lst から項目の最初の出現箇所のみを削除します。`equal?` を使用して等価性をテストします。`delq1!` および `delv1!` も参照してください。

Scheme Procedure: **filter** pred lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-filter)

Scheme Procedure: **filter!** pred lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-filter_0021)

述語 pred を満たす、リスト lst のすべての要素を含むリストを返します。結果リストの要素の順序は、lst の要素の順序と同じです。pred がリスト要素に適用される順序は指定されません。

`filter`はlstを変更しませんが、結果はlstと末尾を共有する場合があります。`filter!`は、戻り値を構築するためにlstを変更する場合があります。

#### 6.6.9.7 リスト検索 [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#List-Searching-1)

以下の手順は、リスト内の特定の要素を検索します。これらの手順は、リストの要素を検索対象オブジェクトと比較するために、異なる比較述語を使用します。検索に失敗した場合は「#f」を返し、そうでない場合は、検索対象オブジェクトと等しい要素を持つサブリストを返します。ここで、等しいかどうかは、使用される等価述語によって異なります。

Scheme Procedure: **memq** x lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-memq)

C 関数: **scm\_memq** (x, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fmemq)

lst のサブリストのうち、car が x と `eq?` する最初のサブリストを返します。ここで、lst のサブリストとは、k が lst の長さより小さい場合に `(list-tail lst k)` によって返される空でないリストのことです。x が lst に含まれていない場合は、`#f` (空のリストではないもの) が返されます。

Scheme手順: **memv** x lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-memv)

C 関数: **scm\_memv** (x, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fmemv)

lst のサブリストのうち、car が x と `eqv?` である最初のサブリストを返します。ここで、lst のサブリストとは、k が lst の長さより小さい場合に `(list-tail lst k)` によって返される空でないリストのことです。x が lst に含まれていない場合は、`#f` (空のリストではないもの) が返されます。

スキーム手順: **member** x lst [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-member)

C 関数: **scm\_member** (x, lst) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fmember)

lst のサブリストのうち、car が x と `equal?` する最初のサブリストを返します。ここで、lst のサブリストとは、k が lst の長さより小さい場合に `(list-tail lst k)` によって返される空でないリストのことです。x が lst に含まれていない場合は、`#f` (空のリストではないもの) が返されます。

拡張された `member` 関数を持つ SRFI-1 も参照してください ([Searching](https://doc.guix.gnu.org/guile/latest/en/guile.html#SRFI_002d1-Searching))。

#### 6.6.9.8 リストマッピング [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#List-Mapping-1)

Schemeでは、リストの要素を反復処理するプロセスを高度に抽象化できるため、リスト処理は非常に便利です。このセクションで紹介する手続きは、リストに対する最も基本的な反復手続きです。これらの手続きは、手続きと1つ以上のリストを引数として受け取り、リストの各要素に手続きを適用します。それぞれの手続きは、戻り値が異なります。

Scheme プロシージャ: **map** proc arg1 arg2 … [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-map)

Scheme プロシージャ: **map-in-order** proc arg1 arg2 … [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-map_002din_002dorder)

C 関数: **scm\_map** (proc, arg1, args) [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-scm_005fmap)

引数が2つだけの場合は、リストarg1の各要素にprocを適用します。引数が2つ以上ある場合は、引数リストの対応する要素にprocを適用します。プロシージャの適用結果はリストに保存され、返されます。`map`の場合、プロシージャの適用順序は指定されません。`map-in-order`は、リストの要素に対して左から右にプロシージャを適用します。

Scheme プロシージャ: **for-each** proc arg1 arg2 … [¶](https://doc.guix.gnu.org/guile/latest/en/guile.html#index-for_002deach)

`map`と同様ですが、手続きは常に左から右に適用され、手続きの適用結果は破棄されます。戻り値は指定されていません。

また、これらの関数を拡張して長さの異なるリストを扱えるようにしたSRFI-1も参照してください（[Fold、Unfold、Map](https://doc.guix.gnu.org/guile/latest/en/guile.html#SRFI_002d1-Fold-and-Map)）。
