# 第3章 raw 入力と出力

> 解説ノートです。原文は https://viewsourcecode.org/snaptoken/kilo/ （© Paul Smith, CC BY 4.0）にあります。

## この章のテーマ

キー入力を受け取る部分と、画面を描く部分を、エディタらしい構造に整えます。描画には curses を使わず、VT100 系のエスケープシーケンスを直接書き出します。

## 手順の流れ

### 1. 入力処理の整理

入力を扱う処理を、役割ごとに関数へ分けます。

- キーを 1 つ読む関数（読めるまで待つ）
- 読んだキーに応じて動作を決める関数
- 終了時に画面を片づける処理

Ctrl-Q で終了させるため、`CTRL_KEY(k)` というマクロを用意します。Ctrl を押した文字は、上位 3 ビットが落ちた値になることを利用して、ビットマスクで表します。

### 2. 画面のクリア

エスケープシーケンスは、`ESC`（27）と `[` に続くコマンドです。

- `ESC [ 2 J`: 画面全体を消す
- `ESC [ H`: カーソルを左上へ戻す

終了時にもこれらを出し、シェルに戻ったときの画面をきれいにします。

### 3. 行頭のチルダ

vim と同じく、各行の先頭に `~` を並べます。これには画面の行数が必要です。

### 4. ウィンドウサイズの取得

`ioctl()` に `TIOCGWINSZ` を渡して、行数と列数を得ます。これが失敗する環境のために、代替の方法も用意します。

1. カーソルを右下へ大きく動かす（実際の端までしか動かない性質を使う）
2. カーソル位置の問い合わせ（`ESC [ 6 n`）を送る
3. 端末からの応答を読み取り、解析して位置を得る

この位置が、画面の大きさになります。

### 5. 描画を 1 回の書き込みにまとめる

小さな `write()` を何度も呼ぶと、ちらつきの原因になります。そこで、可変長の文字列を貯める「追加バッファ」を作り、1 フレーム分をためてから、まとめて書き出します。

### 6. 描画の仕上げ

- 描画の間はカーソルを隠し、描画後に再び表示する
- 全画面を消す代わりに、各行の末尾だけを消す（ちらつきを減らす）
- 空のファイルのときは、画面の中ほどにバージョン付きの案内文を、中央寄せで表示する

### 7. カーソルの移動

カーソルの位置を `cx`、`cy` として保持し、描画のたびにその位置へ動かします。

最初は `w`、`a`、`s`、`d` で動かしますが、矢印キーはエスケープシーケンスで届きます。そこで次のように拡張します。

- `ESC` に続く文字を読んで、矢印キーのシーケンスかどうかを判定する
- 他のキーと区別するために、キーを表す値を `char` の範囲外の整数にする（列挙型で定義する）
- 画面の外へ出ないように、動ける範囲を制限する

### 8. 特殊キー

同じ方法で、次のキーも判定します。

- Page Up / Page Down: 画面の高さ分、上下に動く
- Home / End: 行頭・行末へ動く（端末によってシーケンスが複数ある）
- Delete: 後の章で使う

## 確認ポイント

- 画面全体に `~` が並び、カーソルが左上にある
- 矢印キーでカーソルが動き、画面の端で止まる
- 描画時にちらつかない
