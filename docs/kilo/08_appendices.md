# 8. 付録

## 差分表示の仕組み

このチュートリアルでは、各ステップを差分（diff）として表示します。差分は、現在のステップに進むために前のステップのコードに加える必要のある変更点を示します。以下は、ステップ7の差分の例です。

**ステップ 7** ([kilo.c](https://github.com/snaptoken/kilo-src/blob/icanon/kilo.c) / [icanon](https://github.com/snaptoken/kilo-src/tree/icanon))

```diff
 #include <stdlib.h>
 #include <termios.h>
 #include <unistd.h>
 
 struct termios orig_termios;
 
 void disableRawMode() {
   …
 }
 
 void enableRawMode() {
   tcgetattr(STDIN_FILENO, &orig_termios);
   atexit(disableRawMode);
 
   struct termios raw = orig_termios;
+  raw.c_lflag &= ~(ECHO | ICANON);
 
   tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);
 }
 
 int main() {
   …
 }
```

*コンパイル*

各差分は、編集対象のファイル名（「kilo.c」）、ステップ番号（「Step 7」）、ステップ名（「icanon」）を含むヘッダーから始まります。ファイル名をクリックすると、GitHub 上で現在のステップのファイルのソースコード全体が表示されます。また、右端のステップ名をクリックすると、GitHub 上で現在のステップのすべてのファイルを参照できます（ただし、このチュートリアルでは単一のソースファイルのみを扱っているため、この機能はあまり役に立ちません）。

ヘッダーの後にはファイルの内容が表示されます。追加または変更が必要な行はハイライト表示され、矢印で示されます。変更のない関数は、内容が非表示になった状態で1行にまとめられます。

削除する必要のある行は、赤い背景色で取り消し線が引かれ、 ✕マークで示されます。削除された行は、追加または変更された行の隣にある場合は表示されないため、あまり目にすることはありません。

各差分の下部には、そのステップのコンパイル状態が表示されます。緑色で「コンパイル済み」と表示されている場合は、そのステップの完了後にコードがコンパイルされ、プログラムを実行すると変更が反映されることが期待できます。そのステップで目に見える変更がない場合は、コンパイル状態は青色で「コンパイル済みですが、目に見える効果はありません」と表示されます。まれにコンパイルに失敗する場合は、赤色で「コンパイルできません」と表示されます。

## 行き詰まった場合の対処法

このチュートリアルのコードの中には、特にC言語に慣れていない方にとっては、正確に入力するのが非常に難しいものがあります。行を変更している際に、変更が完了したと思っても、同じ行の別の部分への小さな変更を見落としてしまうことがよくあります。時間をかけて、diffコマンドで表示される変更箇所を文字ごとに比較し、自分のコードと一致していることを確認することが重要です。

エラーが発生したと思われるが、エラー箇所や発生時期がわからない場合は、お使いのコンピューターで、現在実行中の手順に対応する `kilo.c` のバージョンとチュートリアルの `kilo.c` のバージョンの差分を比較してください。[kilo-src](https://github.com/snaptoken/kilo-src) リポジトリには、チュートリアルの各手順に対応する `kilo.c` ソースコードが含まれています。

これを行うには `git` が必要です。`git` をインストールするには（[第 1 章](01_setup.md) を完了していることを前提として）：**Ubuntu/Windows 上の Bash** では、`sudo apt-get install git` を実行します。**Cygwin** では、インストーラーを再度実行し、インストールするパッケージとして `git` を選択します。**macOS** では、コマンドライン ツールをインストールした際に `git` もインストールされているはずです。

`git` をインストールしたら、`git clone https://github.com/snaptoken/kilo-src` を実行して [kilo-src](https://github.com/snaptoken/kilo-src) リポジトリをクローンします。`cd kilo-src` を使用してリポジトリに移動します。リポジトリには、各ステップに対応する [tag](https://git-scm.com/book/en/v2/Git-Basics-Tagging) があり、ステップ名がリポジトリ内のそのステップのコミットを指しています。したがって、`icanon` という名前のステップのソースコードを取得するには、`git checkout icanon` を実行します。これで、`kilo.c` ファイルにはそのステップのコードが含まれるようになります。`git diff --no-index -b ../path/to/your/kilo.c kilo.c` のようなコマンドを実行することで、自分の `kilo.c` とこの `kilo.c` を比較できます。これにより、リポジトリにあるものと同じになるように `kilo.c` に加える必要のある変更点が表示されます。`-b` オプションは空白文字を無視するため、チュートリアルとは異なるインデントスタイルを使用しても問題ありません。

## 自分で追加できる機能のアイデア

`kilo` を独自に拡張したい場合は、しばらくの間、実際に `kilo` をテキストエディタとして使ってみることをお勧めします。テキストエディタで慣れ親しんでいる機能が `kilo` にはないことに、すぐに気づくでしょう。それらの機能こそ、追加すべき機能です。そして、`kilo.c` を編集する際には、`kilo` を使うべきです。

まだアイデアを探しているなら、難易度が上がる順に並べたリストを以下に挙げます。

* **その他のファイルタイプ**: お気に入りの言語の構文強調表示ルールを `HLDB` 配列に追加します。
* **行番号**: ファイルの各行の左側に行番号を表示します。
* **ソフトインデント**: タブの代わりにスペースを使いたい場合は、Tab キーで `\t` の代わりにスペースを挿入するように設定してください。また、Backspace キーで Tab キー分のスペースを削除するように設定することもできます。
* **自動インデント**: 新しい行を開始すると、前の行と同じレベルにインデントされます。
* **改行**: ユーザーが画面の末尾を超えて入力しようとしたときに、テキストに改行を挿入します。単語を分割するような場所には改行を挿入しないようにしてください。
* **ソフトラップ行**: 行が画面の幅よりも長い場合、水平スクロールの代わりに、画面上で複数の行を使用して表示します。
* **ncurses を使用する**: [ncurses](https://en.wikipedia.org/wiki/Ncurses) ライブラリは、低レベルの端末とのやり取りの多くを処理し、プログラムの移植性を高めます。
* **コピーと貼り付け**: ユーザーがテキストを選択できるようにし、Ctrl+C を押すと選択したテキストをコピーし、Ctrl+V を押すとコピーしたテキストを貼り付けられるようにします。
* **設定ファイル**: `kilo` に設定ファイル（例えば `.kilorc` という名前）を読み込ませて、現在定数となっている `KILO_TAB_STOP` や `KILO_QUIT_TIMES` などのオプションを設定できるようにします。今後、設定可能な項目を増やしていく予定です。
* **モーダル編集**: [vim](http://www.vim.org/)がお好きなら、`kilo`をvimのように動作させ、ユーザーが「挿入モード」にするためにiキーを押し、次に「通常モード」に戻るためにEscapeキーを押すようにします。次に、基本的な移動コマンド(hjkl)から始めて、お気に入りのvimコマンドをすべて追加していきます。
* **複数のバッファ**: 複数のファイルを同時に開くことができ、それらを切り替える方法がある。

このようなチュートリアルを今後も作成していく予定です。すべて[viewsourcecode.org/snaptoken](http://viewsourcecode.org/snaptoken)で公開されます。新しいチュートリアルが公開されるたびにメールで通知を受け取るための登録リンクも掲載されています。また、ウェブ上の他のユーザーが作成した同様のチュートリアルの一覧もあります。

次のチュートリアルは、今回のものとは少し異なります。例えば、700行のシェルスクリプトで記述された[パスワードマネージャー](https://passwordstore.org/)や、難読化されたRubyの大きな四角形で実装された[Webマイクロフレームワーク](https://github.com/camping/camping)などが考えられます。

これらのチュートリアルに共通するのは、実際のオープンソースソフトウェアプロジェクトのコードを読み解き、理解するための、段階的な自己構築型アプローチです。もしレゴのようなおもちゃで、物理的な構造物ではなくプログラムを組み立てるものがあったとしたら、「snaptoken」という名前はまさにぴったりだと思います。私がこのようなチュートリアルを通して実現したいのは、まさにそのような体験です。

## 貢献方法

テキスト、コード、HTML/CSSの変更など、どのような形であれ、貢献を歓迎します。

テキストは、[kilo-tutorial](https://github.com/snaptoken/kilo-tutorial)リポジトリの`doc/`ディレクトリにあります。各章はMarkdown（`.md`）ファイルです。

HTML/CSSファイルは`doc/html_in/`ディレクトリにあります。

コードは`steps.diff`にありますが、これは人間が編集できるものではありません。これは[leg](https://github.com/snaptoken/leg)というプログラムによって生成されます。

テキストに大幅な変更を加える場合は、変更内容をプレビューするために最終的な静的HTMLファイルを生成したいと思うでしょう。以下は、`leg`プログラムを使用してHTML出力を生成する方法です。

1. [Ruby](https://www.ruby-lang.org/en/documentation/installation/)がインストールされている必要があります。
2. `gem install snaptoken`を実行して`leg`バイナリをインストールします（`sudo`が必要になる場合があります）。
3. `kilo-tutorial`リポジトリ内で`leg doc`を実行して、`doc/html_out/`と`doc/html_offline/`に静的HTMLファイルを生成します。
4. `leg doc` を実行すると、各ステップの差分が隠しドットファイルにキャッシュされるため、`doc/` フォルダー内のファイルのみを変更している限り、`leg doc -c` を実行してキャッシュされた差分を使用し、HTML 出力をはるかに高速に再生成できます。

テキストにちょっとした修正を加えるだけであれば、この手順をすべて踏む必要はありません。章のマークダウンファイルに変更を加えて、[プルリクエストを送信](https://github.com/snaptoken/kilo-tutorial/pulls)するだけです。
