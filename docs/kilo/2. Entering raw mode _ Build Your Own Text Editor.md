生データモードに入ります
=================

ユーザーのキー入力を読み取ってみましょう。（追加する必要のある行はハイライト表示され、矢印で示されています。）

[kilo.c](https://github.com/snaptoken/kilo-src/blob/read/kilo.c)

ステップ3

[read](https://github.com/snaptoken/kilo-src/tree/read)

#include <unistd.h>int main() { char c; while (read(STDIN_FILENO, &c, 1) == 1); return 0;}

♐ ︎ コンパイル

`read()` と `STDIN_FILENO` は `<unistd.h>` から取得されます。ここでは、`read()` 関数に標準入力から `1` バイトを読み込み、変数 `c` に格納するように指示しています。そして、読み込むバイトがなくなるまでこの処理を繰り返します。`read()` 関数は読み込んだバイト数を返し、ファイルの末尾に達すると `0` を返します。

`./kilo` を実行すると、ターミナルが標準入力に接続され、キーボード入力が `c` 変数に読み込まれます。ただし、デフォルトではターミナルは **正規モード**（**クックドモード**とも呼ばれます）で起動します。このモードでは、キーボード入力はユーザーが Enter キーを押したときにのみプログラムに送信されます。これは多くのプログラムで便利です。ユーザーはテキストを一行入力し、バックスペースキーでエラーを修正して入力が思い通りになるまで調整し、最後に Enter キーを押してプログラムに送信できます。しかし、テキストエディタのような複雑なユーザーインターフェイスを持つプログラムではうまく機能しません。キー入力があったらすぐに処理して、即座に対応できるようにしたいのです。

私たちが求めているのは**rawモード**です。残念ながら、ターミナルをrawモードに設定するための簡単なスイッチはありません。rawモードは、ターミナル内の多数のフラグをオフにすることで実現します。この章では、その手順を段階的に説明していきます。

上記のプログラムを終了するには、Ctrl+Dを押して`read()`にファイルの終わりに達したことを伝えます。または、Ctrl+Cを押してプロセスを即座に終了させることもできます。

[終了するにはqキーを押してください?](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#press-q-to-quit)
-----------------------------------------------------------------------------------------------------

正規モードの動作を説明するために、ユーザーから「aq keypress」というキー入力があったらプログラムを終了するようにします。（変更が必要な行は、追加が必要な行と同様にハイライト表示されています。）

[kilo.c](https://github.com/snaptoken/kilo-src/blob/press-q/kilo.c)

ステップ4

[press-q](https://github.com/snaptoken/kilo-src/tree/press-q)

#include <unistd.h>int main() { char c; while (read(STDIN_FILENO, &c, 1) == 1 && c != 'q'); return 0;}

♐ ︎ コンパイル

このプログラムを終了するには、テキスト行の中に「q」を含む行を入力し、Enterキーを押してください。プログラムはテキスト行を1文字ずつ読み込み、「q」を読み込んだ時点でwhileループが停止し、プログラムが終了します。「q」以降の文字は入力キューに未読のまま残され、プログラム終了後もその入力がシェルに渡されることがあります。

[エコーをオフにする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#turn-off-echoing )
------------------------------------------------------------------------------------------------------

端末の属性を設定するには、(1) `tcgetattr()` を使用して現在の属性を構造体に読み込み、(2) 構造体を手動で変更し、(3) 変更した構造体を `tcsetattr()` に渡して新しい端末属性を書き出す、という手順があります。この方法で `ECHO` 機能を無効にしてみましょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/echo/kilo.c)

ステップ5

[echo](https://github.com/snaptoken/kilo-src/tree/echo)

#include <termios.h>#include <unistd.h>void enableRawMode() { struct termios raw; tcgetattr(STDIN_FILENO, &raw); raw.c_lflag &= ~(ECHO); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { enableRawMode(); char c; while (read(STDIN_FILENO, &c, 1) == 1 && c != 'q'); return 0;}

♐ ︎ コンパイル

`struct termios`、`tcgetattr()`、`tcsetattr()`、`ECHO`、および`TCSAFLUSH`はすべて`<termios.h>`から来ています。

`ECHO` 機能を使うと、入力したキーがターミナルに表示されるので、入力内容を確認できます。これは標準モードでは便利ですが、raw モードでユーザー インターフェイスを慎重にレンダリングしようとすると邪魔になります。そのため、この機能を無効にします。このプログラムは前のステップのプログラムと同じことをしますが、入力内容は表示されません。たとえば `sudo` を使用する際にターミナルでパスワードを入力する必要があった場合、このモードはお馴染みかもしれません。

プログラム終了後、シェルによっては、入力した内容がターミナルに反映されない場合があります。しかし、心配はいりません。入力内容は引き続き認識されます。Ctrl+Cを押してシェルへの入力行を再開し、「reset」と入力してEnterキーを押してください。ほとんどの場合、これでターミナルは正常な状態に戻ります。それでも解決しない場合は、ターミナルエミュレータを再起動してください。次のステップで、この問題全体を解決します。

端末属性は、`tcgetattr()` 関数を使用して `termios` 構造体に読み込むことができます。属性を変更した後、`tcsetattr()` 関数を使用して端末に適用できます。`TCSAFLUSH` 引数は、変更を適用するタイミングを指定します。この場合、保留中のすべての出力が端末に書き込まれるまで待機し、読み込まれていない入力はすべて破棄されます。

`c_lflag` フィールドは「ローカル フラグ」用です。macOS の `<termios.h>` のコメントでは、「他の状態のダンプ場所」と説明されています。したがって、おそらく「その他のフラグ」と考えるべきでしょう。その他のフラグ フィールドは `c_iflag` (入力フラグ)、`c_oflag` (出力フラグ)、および `c_cflag` (制御フラグ) で、raw モードを有効にするには、これらすべてを変更する必要があります。

`ECHO` は [bitflag](https://en.wikipedia.org/wiki/Bit_field) であり、バイナリでは `000000000000000000000000000001000` と定義されます。この値に対してビットごとの NOT 演算子 (`~`) を使用すると、`111111111111111111111111111110111` になります。次に、この値を flags フィールドとビットごとの AND 演算すると、flags フィールドの 4 番目のビットが `0` になり、他のすべてのビットは現在の値のままになります。このようにビットを反転させるのは C 言語ではよくあることです。

[終了時に生モードを無効にする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#disable-raw-mode-at-exit)
----------------------------------------------------------------------------------------------------------------------

ユーザーに配慮して、プログラム終了時に端末の元の属性を復元しましょう。`termios`構造体のコピーを元の状態で保存し、プログラム終了時に`tcsetattr()`を使用して端末に適用します。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/atexit/kilo.c)

ステップ6

[atexit](https://github.com/snaptoken/kilo-src/tree/atexit)

#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig_termios);}void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_lflag &= ~(ECHO); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { … }

♐ ︎ コンパイル

`atexit()` は `<stdlib.h>` に含まれています。この関数を使用して、`disableRawMode()` 関数を登録し、プログラム終了時に自動的に呼び出されるようにします。これは、`main()` 関数からの戻りによる終了でも、`exit()` 関数の呼び出しによる終了でも同様です。こうすることで、プログラム終了時に端末属性が元の状態のままになることを保証できます。

元の端末属性はグローバル変数`orig_termios`に格納します。変更を加える前に、`orig_termios`構造体を`raw`構造体に代入してコピーを作成します。

プログラム終了後、シェルに未処理の入力が反映されなくなることに気づくかもしれません。これは、プログラム終了時に`tcsetattr()`に`TCSAFLUSH`オプションが渡されるためです。前述のとおり、このオプションは端末に変更を適用する前に、読み取れなかった入力を破棄します。（注：Cygwinでは何らかの理由でこの動作は発生しませんが、入力を1バイトずつ読み込むようになれば問題ありません。）

[正規モードをオフにする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#turn-off-canonical-mode)
--------------------------------------------------------------------------------------------------------------------

`ICANON`フラグを使用すると、正規モードをオフにできます。これにより、入力データを行単位ではなく、バイト単位で読み込むようになります。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/icanon/kilo.c)

ステップ7

[icanon](https://github.com/snaptoken/kilo-src/tree/icanon)

#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_lflag &= ~(ECHO | ICANON); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { … }

♐ ︎ コンパイル

`ICANON`は`<termios.h>`から来ています。入力フラグ（`c_iflag`フィールドにあるもの）は、一般的に`ICANON`のように`I`で始まります。しかし、`ICANON`は入力フラグではなく、`c_lflag`フィールドにある「ローカル」フラグです。そのため、紛らわしいのです。

これで、qキーを押すとすぐにプログラムが終了します。

[キー入力の表示](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#display-keypresses)
----------------------------------------------------------------------------------------------------------

生データモードでの入力がどのように機能するかをよりよく理解するために、`read()` で読み込んだ各バイトを出力してみましょう。各文字の数値ASCII値と、それが印刷可能な文字であればその文字自体も出力します。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/keypresses/kilo.c)

ステップ8

[keypresses](https://github.com/snaptoken/kilo-src/tree/keypresses)

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { … }int main() { enableRawMode(); char c; while (read(STDIN_FILENO, &c, 1) == 1 && c != 'q') { if (iscntrl(c)) { printf("%d\n", c); } else { printf("%d ('%c')\n", c, c); } } return 0;}

♐ ︎ コンパイル

`iscntrl()` は `<ctype.h>` から、`printf()` は `<stdio.h>` から来ています。

`iscntrl()` は、文字が制御文字かどうかを判定します。制御文字とは、画面に表示したくない非表示文字のことです。ASCIIコード0～31はすべて制御文字であり、127も制御文字です。ASCIIコード32～126はすべて表示可能な文字です。（すべての文字については、[ASCIIテーブル](http://asciitable.com/)を参照してください。）

`printf()` は、バイトを複数の形式で表示できます。`%d` は、バイトを10進数（ASCIIコード）としてフォーマットするように指示し、`%c` は、バイトを文字として直接書き出すように指示します。

これは非常に便利なプログラムです。さまざまなキー操作が、読み取るバイト列にどのように変換されるかを示してくれます。ほとんどの通常のキーは、それが表す文字に直接変換されます。しかし、矢印キー、Escapeキー、Page Upキー、Page Downキー、Homeキー、Endキー、Backspaceキー、Deleteキー、Enterキーを押したときに何が起こるか試してみてください。Ctrlキーとの組み合わせ、例えばCtrl-A、Ctrl-Bなども試してみてください。

いくつか興味深い点に気づくでしょう。

矢印キー、Page Up、Page Down、Home、End キーはすべて、端末に 3 バイトまたは 4 バイトを入力します。入力内容は、`27`、`'['`、そして 1 文字または 2 文字です。これはエスケープシーケンスと呼ばれます。すべてのエスケープシーケンスは `27` バイトで始まります。Escape キーを押すと、入力として `27` バイトが 1 つ送信されます。
* バックスペースはバイト127です。削除は4バイトのエスケープシーケンスです。
* Enter はバイト `10` で、これは改行文字、つまり `'\n'` です。
* Ctrl-A は 1、Ctrl-B は 2、Ctrl-C は…ああ、これでプログラムが終了しますね。しかし、正常に動作する Ctrl キーの組み合わせは、文字 A～Z をコード 1～26 にマッピングしているようです。

ちなみに、もし誤ってCtrl+Sを押してしまった場合、プログラムがフリーズしたように見えるかもしれません。これは、プログラムに[出力の送信を停止するように](https://en.wikipedia.org/wiki/Software_flow_control)指示を出したためです。出力の送信を再開するには、Ctrl+Qを押してください。

また、Ctrl+Z（またはCtrl+Y）を押すと、プログラムがバックグラウンドに移行します。フォアグラウンドに戻すには、`fg`コマンドを実行してください。（ただし、`read()`がエラー発生を示す`-1`を返すため、その直後にプログラムが終了する場合があります。これはmacOSで発生する現象ですが、Linuxでは`read()`呼び出しを適切に再開できるようです。）

[Ctrl-C と Ctrl-Z シグナルを無効にする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#turn-off-ctrl-c-and-ctrl-z-signals)
------------------------------------------------------------------------------------------------------------------------------------------

デフォルトでは、Ctrl+C を押すと現在のプロセスに `SIGINT` シグナルが送信され、プロセスが終了します。また、Ctrl+Z を押すと現在のプロセスに `SIGTSTP` シグナルが送信され、プロセスが一時停止します。これらのシグナルの送信を両方とも無効にしてみましょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/isig/kilo.c)

ステップ9

[isig](https://github.com/snaptoken/kilo-src/tree/isig)

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_lflag &= ~(ECHO | ICANON | ISIG); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { … }

♐ ︎ コンパイル

`ISIG`は`<termios.h>`から来ています。`ICANON`と同様に`I`で始まりますが、入力フラグではありません。

これで、Ctrl-Cは3バイトとして、Ctrl-Zは26バイトとして読み取れるようになりました。

これにより、macOS の Ctrl-Y も無効になります。Ctrl-Y は Ctrl-Z に似ていますが、プログラムが入力を読み取るまで待機してから一時停止します。

[Ctrl-S と Ctrl-Q を無効にする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#disable-ctrl-s-and-ctrl-q)
----------------------------------------------------------------------------------------------------------------------

デフォルトでは、Ctrl-S と Ctrl-Q は [ソフトウェアフロー制御](https://en.wikipedia.org/wiki/Software_flow_control) に使用されます。Ctrl-S を押すと、Ctrl-Q を押すまで端末へのデータ送信が停止します。これは、プリンターなどのデバイスが追いつくまでデータ送信を一時停止したい場合などに使われる機能です。この機能を無効にしましょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/ixon/kilo.c)

[ixon](https://github.com/snaptoken/kilo-src/tree/ixon)

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_iflag &= ~(IXON); raw.c_lflag &= ~(ECHO | ICANON | ISIG); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { … }

♐ ︎ コンパイル

`IXON` は `<termios.h>` から来ています。`I` は「入力フラグ」の略で（これまで見てきた他の `I` フラグとは異なり、これは入力フラグです）、`XON` は Ctrl-S と Ctrl-Q によって生成される 2 つの制御文字の名前から来ています。つまり、送信を一時停止する `XOFF` と送信を再開する `XON` です。

これで、Ctrl-Sは「19」バイトとして、Ctrl-Qは「17」バイトとして読み取れるようになりました。

[Ctrl+Vを無効にする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#disable-ctrl-v)
--------------------------------------------------------------------------------------------------

システムによっては、Ctrl+V を押すと、端末が次の文字の入力を待ってから、その文字をそのまま送信します。例えば、Ctrl+C を無効にする前は、Ctrl+V を押してから Ctrl+C を押すことで、3 バイトを入力できたかもしれません。この機能は、`IEXTEN` フラグを使用して無効にできます。

`IEXTEN`を無効にすると、macOSにおけるCtrl+Oの動作も修正されます。macOSのターミナルドライバは、通常、この制御文字を破棄するように設定されているためです。

[Ctrl-M の修正](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#fix-ctrl-m)
------------------------------------------------------------------------------------------

プログラムを実行してCtrlキーを押しながらアルファベットを順番に見ていくと、M以外のすべての文字が表示されるはずです。Ctrl+Mは奇妙な動作をします。アルファベットの13番目の文字なので「13」と読み取られるはずですが、「10」と読み取られています。Ctrl+Jでも既に「10」と表示されます。他に「10」と表示されるキーは何でしょうか？それはEnterキーです。

どうやら、端末はユーザーが入力したキャリッジリターン（`13`、`'\r'`）を改行（`10`、`'\n'`）に自動的に変換しているようです。この機能を無効にしましょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/icrnl/kilo.c)

ステップ12

[icrnl](https://github.com/snaptoken/kilo-src/tree/icrnl)

♐ ︎ コンパイル

`ICRNL`は`<termios.h>`から来ています。`I`は「入力フラグ」、`CR`は「キャリッジリターン」、`NL`は「改行」を表します。

これで、Ctrl+M は「13」（キャリッジリターン）として読み取られ、Enter キーも「13」として読み取られるようになりました。

[すべての出力処理をオフにする](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#turn-off-all-output-processing)
----------------------------------------------------------------------------------------------------------------------------------

端末は出力側でも同様の変換を行っていることが分かります。入力された改行文字（`"\n"`）は、キャリッジリターンとそれに続く改行文字（`"\r\n"`）に変換されます。端末は新しい行を開始するために、これらの文字の両方を必要とします。キャリッジリターンはカーソルを現在の行の先頭に戻し、改行文字はカーソルを1行下に移動させ、必要に応じて画面をスクロールします。（これらの2つの異なる操作は、タイプライターやテレタイプ端末の時代に由来します。）

`OPOST`フラグをオフにすることで、すべての出力処理機能を無効にします。実際には、デフォルトで有効になっている出力処理機能は、おそらく`"\n"`から`"\r\n"`への変換のみでしょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/opost/kilo.c)

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON); raw.c_oflag &= ~(OPOST); raw.c_cflag |= (CS8); raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG); tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { … }

♎ ︎ コンパイルはされるが、目に見える効果はない

`BRKINT`、`INPCK`、`ISTRIP`、および`CS8`はすべて`<termios.h>`から来ています。

この手順は、これらのフラグが既にオフになっているか、最新のターミナルエミュレータには実際には適用されないため、おそらく目に見える効果はないでしょう。しかし、かつては（誰かによって）これらのフラグをオフにすることが「rawモード」を有効にする一部と考えられていたため、私たちは（それが誰であれ）その伝統をプログラムで引き継いでいます。

私の知る限りでは：

* `BRKINT` がオンになっている場合、[ブレーク条件](https://www.cmrr.umn.edu/%7Estrupp/serial.html#2_3_3) が発生すると、`Ctrl-C` を押したときのように、プログラムに `SIGINT` シグナルが送信されます。
* `INPCK`はパリティチェックを有効にしますが、これは最新の端末エミュレータには適用されないようです。
* `ISTRIP` は、入力バイトの8ビット目を削除し、そのビットを `0` に設定します。おそらく既に無効になっています。
* `CS8`はフラグではなく、複数のビットを持つビットマスクです。他のフラグとは異なり、ビットごとのOR演算子（`|`）を使用して設定します。これにより、文字サイズ（CS）が1バイトあたり8ビットに設定されます。私のシステムでは、既にそのように設定されています。

[`read()` のタイムアウト](https://viewsourcecode.org/snaptoken/kilo/02.enteringRawMode.html#a-timeout-for-read)
--------------------------------------------------------------------------------------------------------------

現在、`read()` 関数はキーボードからの入力を無期限に待機してから戻ります。ユーザー入力を待っている間に画面上でアニメーションを実行したい場合はどうすればよいでしょうか？タイムアウトを設定することで、一定時間入力がない場合に `read()` 関数が戻るようにすることができます。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/vmin-vtime/kilo.c)

ステップ16

[vmin-vtime](https://github.com/snaptoken/kilo-src/tree/vmin-vtime)

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void disableRawMode() { … }void enableRawMode() { tcgetattr(STDIN_FILENO, &orig_termios); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON); raw.c_oflag &= ~(OPOST); raw.c_cflag |= (CS8); raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG); raw.c_cc[VMIN] = 0; raw.c_cc[VTIME] = 1; tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);}int main() { enableRawMode(); while (1) { char c = '\0'; read(STDIN_FILENO, &c, 1); if (iscntrl(c)) { printf("%d\r\n", c); } else { printf("%d ('%c')\r\n", c, c); } if (c == 'q') break; } return 0;}

♐ ︎ コンパイル

`VMIN`と`VTIME`は`<termios.h>`から取得されます。これらは`c_cc`フィールドへのインデックスであり、`c_cc`は「制御文字」を意味し、さまざまな端末設定を制御するバイト配列です。

`VMIN` 値は、`read()` が戻り値を返すまでに必要な入力バイト数の最小値を設定します。ここでは `0` に設定することで、読み込む入力が少しでもあればすぐに `read()` が戻り値を返すようにします。`VTIME` 値は、`read()` が戻り値を返すまでの最大待機時間を設定します。これは 10 分の 1 秒単位なので、10 分の 10 秒、つまり 100 ミリ秒に設定します。`read()` がタイムアウトすると `0` が返されます。これは、通常の戻り値が読み込まれたバイト数であることを考えると当然です。

プログラムを実行すると、`read()` がタイムアウトする頻度を確認できます。入力がない場合、`read()` は `c` 変数を設定せずに戻り、`c` の値は `0` のままになるため、出力には `0` が表示されます。非常に速く入力すると、`read()` はキーを押すたびにすぐに戻るため、10分の1秒に1回しかキー入力を読み取れないということはありません。

**Windows 版 Bash** を使用している場合、`read()` が依然として入力待ちでブロックされることに気づくかもしれません。`VTIME` の値は関係ないようです。幸いなことに、テキストエディタでは基本的に入力待ちでブロックされるため、これは大きな問題にはなりません。

#include <ctype.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void die(const char *s) { perror(s); exit(1);}void disableRawMode() { … }void enableRawMode() { … }int main() { … }

♎ ︎ コンパイルはされるが、目に見える効果はない

`perror()` は `<stdio.h>` から、`exit()` は `<stdlib.h>` から来ています。

ほとんどのCライブラリ関数は、エラーが発生した場合、グローバル変数`errno`にエラー内容を示す値を設定します。`perror()`はグローバル変数`errno`を参照し、それに対応する詳細なエラーメッセージを出力します。また、エラーメッセージを出力する前に、渡された文字列も出力します。これは、コードのどの部分がエラーの原因となったのかを示すためのものです。

エラーメッセージを出力した後、終了ステータス「1」でプログラムを終了します。これは失敗を示します（ゼロ以外の値はすべて失敗を示します）。

ライブラリ呼び出しがそれぞれ失敗していないかチェックし、失敗した場合は `die()` を呼び出しましょう。

[kilo.c](https://github.com/snaptoken/kilo-src/blob/error-handling/kilo.c)

#include <ctype.h>#include <errno.h>#include <stdio.h>#include <stdlib.h>#include <termios.h>#include <unistd.h>struct termios orig_termios;void die(const char *s) { … }void disableRawMode() { if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig_termios) == -1) die("tcsetattr");}void enableRawMode() { if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) die("tcgetattr"); atexit(disableRawMode); struct termios raw = orig_termios; raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON); raw.c_oflag &= ~(OPOST); raw.c_cflag |= (CS8); raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG); raw.c_cc[VMIN] = 0; raw.c_cc[VTIME] = 1; if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw) == -1) die("tcsetattr");}int main() { enableRawMode(); while (1) { char c = '\0'; if (read(STDIN_FILENO, &c, 1) == -1 && errno != EAGAIN) die("read"); if (iscntrl(c)) { printf("%d\r\n", c); } else { printf("%d ('%c')\r\n", c, c); } if (c == 'q') break; } return 0;}

♐ ︎ コンパイル

`errno`と`EAGAIN`は`<errno.h>`から取得されます。

`tcsetattr()`、`tcgetattr()`、および`read()`はすべて、失敗した場合に`-1`を返し、エラーを示すために`errno`値を設定します。

Cygwinでは、`read()`がタイムアウトすると、本来返されるべき`0`ではなく、`errno`が`EAGAIN`の`-1`を返します。Cygwinで正しく動作させるには、`EAGAIN`をエラーとして扱わないようにします。

`tcgetattr()` を失敗させる簡単な方法は、標準入力として端末ではなくテキストファイルまたはパイプを指定することです。ファイルを標準入力として指定するには、`./kilo <kilo.c` を実行します。パイプを指定するには、`echo test | ./kilo` を実行します。どちらの場合も、`tcgetattr()` から `Inappropriate ioctl for device` のような同じエラーが発生するはずです。
